**任何测量和自动化测试，都要先断言它自己的前提成立**，再去看结果。
不断言的话，最常见的失败不是报错，而是**安静地通过**——那比失败危险得多。

**Why:** 2026-07-25 做 omni 大脑和 VAD 调参时，同一天撞了三次，形态各不相同：

1. **测试对象在测量期间是崩的**。P1 并发/取消用例：MLX 线程 bug 让聊天轮从 2.5s
   缩到 700ms，于是「sleep 1 秒后发第二路应得 503」和「取消正在跑的请求」**同时假阳性**——
   worker 早空了。表面看是「并发和取消功能坏了」，掩盖了真正的根因。
   → 修法：`check("被拒时首路仍在跑", not task.done())`。

2. **输入信号是空的**。P0 基准用 macOS `say` 生成测试语音，而新的中文神经语音
   (Flo/Eddy/Grandma…) **接受 `-o` 却静默写出 ~0.02s 的桩**。模型什么都没听见，
   每个场景都回同一句问候，跑出一整张「看起来很真」的延迟表。
   → 修法：换 `Tingting`，并断言时长 `if secs < MIN_CLIP_S: raise`。

3. **被测系统根本没在运行那条代码**。VAD 参数扫描时 daemon 处于 `idle`，
   而 VAD 只在 LISTENING 下运行（其余状态 `vad.reset()` 后直接 return），
   `vad_active` 恒为 False → **每组配置都测出完美的 0%**，看着像「参数全都最优」。
   → 修法：测量前 `ensure_listening()`，且每组数据标注期间是否转入 idle。

第四种变体（不算「空气」但同类）：**输入不受控**。在活麦上顺序 A/B 不同 VAD 参数，
环境噪声在两次测量间漂移了 30dB，跑出 threshold 0.7 比 0.5「更差」这种物理上
不可能的结果——比的是环境不是参数。→ 修法：同一段固定音频离线回放，或固定语料播放。

同日做 [[vad-asr-tuning-results]] 时又添了八种新形态,**每一种都产出了一张漂亮的表**:

5. **宽带指标正常,关键频段已经死了。** 播放语料的录音宽带上语音比静音高 15.4 dB,
   很体面;按频段拆开,1–3.4kHz 辅音带里语音比房间噪声**低 2.6 dB**。silero 只截出
   4/12,而同一套语料的干净数字文件是 12/12。→ 修法:录完立刻算**辅音带信噪比**并
   当硬闸门,不合格就拒绝进入扫参。总能量会替你把失败藏起来。
6. **对齐锚点被杂音顶掉。** 靠开头 1kHz 标记音对齐,衰减 12dB 那一轨的标记被一声
   房间杂音盖过,算出的偏移差 2.45 秒——检查表照样打印得整整齐齐。→ 修法:改用整段
   68 秒能量包络互相关(锚点越长越难被冒充),并断言语音窗口确实比间隙响。
7. **指标口径把失败算成成功。** 扫参把「一个 20 秒大段吞掉 9 句」记成 9 次召回,
   该配置在表里是 12/12,实际 ASR 转写只有 3/12、CER 47.8。→ 修法:按**下游真正消费的
   单位**记账——一段就是一轮,一轮只送一条指令,其余算漏。
8. **`0 == 0` 被当成验证通过。** 「fsmn 忽略 threshold」那条断言跑在一段太安静的
   噪声上,两组参数都切出 0 段,于是报「一致」。→ 修法:验证「两者相同」时必须先断言
   两者**非空**,否则显式报无效。
9. **容差比它要分辨的间距还大。** 匹配用了 ±0.25s 容差,而语料里最短句间距 0.8s;
   正确切成两段被判成粘连。→ 修法:要求与真值窗口有**实打实的重叠**,别用 padding。

10. **采集工具静默丢采样。** ffmpeg + avfoundation 在这台 Mac 上稳定丢 23%
    (20.5 秒墙钟录到 15.9 秒,原生 48kHz 不重采样也一样),不报错。录出来不只是短,
    **时间轴是拼接的**,任何基于时间的对齐都锁不住。→ 修法:录完断言
    `实际时长/墙钟 ≈ 1`。换 `sounddevice`(PortAudio)后是 0.992。
11. **两个对象在不同条件下比较。** 两只麦克风一远一近,信噪比差 15.5dB,直接比 CER
    比的是距离不是麦克风。→ 修法:把干净那一份**掺入它自己的底噪**降到另一份的
    信噪比再比。结论从「差一倍」变成「多错 2 个字」。

12. **仪器本身不可复现,而且没人怀疑过它。** 整套 VAD 调参用 Matcha 合成语料,
    而 **Matcha 是流匹配模型,每次从新的高斯噪声起步**:同一个「停」三次分别是
    0.29 / 0.39 / 0.41 秒(41% 抖动),长文本也差 1%。于是同一份 Matcha 数字语料
    解码一次 11/14、一次 13/14——看起来像系统在波动,其实是尺子在变。
    影响分两半:**跑在同一份录音上的对比仍然有效**(480 组配置吃的是同一批字节);
    但**一切跨批次重新生成语料的绝对结论都不可信**——「0.27 秒的单音节指令不可靠」
    这条恰好用了短的那次抽样。→ 修法:换 edge-tts(裁剪后时长逐次完全一致,
    0.370/0.370/0.370),并在选定 TTS 前先**合成三次比时长**。
    顺带 edge-tts 的识别率也高得多:6 音色 84 句 **83/84 逐字全对 CER 0.012**,
    Matcha 13/14 CER 0.143——用一个自己就念不清的合成器当语料,
    等于把合成缺陷记到声学链路头上。

还有一条不是测量缺陷但同样会误导:**采样太短就是在测天气**。90 秒噪声录一次抓到
一声撞击、再录一次什么都没有(误触发全 0,看着像「参数全都完美」)。改成 5 分钟才
稳定。看到「完美的 0」先怀疑采样量。

**How to apply:**
- 每个测量函数开头断言前提（服务在跑 / 麦克风开着 / 输入非空 / 被测项确实在执行）。
- 结果里带上前提的证据（段时长、电平、状态、样本数），不要只报最终指标。
- **看到「全部通过」或「完美的 0」先怀疑测量本身**，尤其当它与之前的观测矛盾时
  （47% → 0% 就该立刻停下来查，而不是高兴）。
- 对照实验必须固定输入；环境会变的东西不能当作常量。
- **先验证仪器再验证被测物**：选定合成器/采集工具前，同一输入跑三次比时长与哈希；
  比较两个对象前，先把它们拉到同一条件下。尺子会变这件事，没人会主动去怀疑。
